# Этап 9: понимание русских инструкций

Протокол до обучения и просмотра финальных ответов. По запросу пользователя
приоритет перенесён с следующего streaming-пилота на русский язык.

## Вопрос и пределы опыта

Может ли существующая сеть научиться выполнять русские инструкции с разным
порядком слов, копированием и отрицанием, сохранив прежние навыки?
Это контролируемый искусственный язык про четыре переменные, а не свободная
русская речь. Выход — цифра либо собственные записи и цифра. Входной текст
целиком доступен вниманию. Учитель при выводе не используется.

Смысловые проверки вдохновлены исследованиями
[SCAN](https://arxiv.org/abs/1711.00350) и
[CFQ](https://arxiv.org/abs/1912.09713): знакомые элементы соединяются по-новому.
Наши данные собственные; результаты не являются оценками на SCAN или CFQ.

## Модель и данные

- Продолжаем выбранные по validation веса этапа 7: history / fly / rewired /
  no_edges, по три исходных seed. Три слоя, ширина 96. Графовые варианты
  используют 256 узлов и 7514 связей; это не полный мозг мухи.
- Новые входные эмбеддинги для русских слов и букв. Словарь собран только из
  train. Старые входы и выходной алфавит сохранены; preflight проверяет
  исходное равенство вероятностей старой модели. Новое слово — обучаемый ID,
  а не программное обозначение операции. Незнакомые слова разбиваются на буквы;
  это обеспечивает представимость, но не знание их смысла.
- 18000 train, 240 dev, 240 dev_phrases. Четыре переменные; 2–6 операций:
  запись, копирование, сохранение без изменения, выбор «не X, а Y».
  Числа 0–9: 70% представлений словами, остальные цифрами.
- Структурные сигнатуры не содержат имён и чисел. Train — hash buckets 0–7,
  dev — 8, test — 9. Структуры контрастных пар исключены из train/dev.
  Правильные цифры сбалансированы внутри трёх ролей запроса: исходное,
  ранее записанное, последнее записанное. При обучении запрещены две подряд
  связанные операции копирования.
- Финальные наборы: test 300; новые фразы 300; новые имена 300; длины 12/20 —
  180; связанные копирования — 180; направление копирования — 100 пар;
  отрицание — 100 пар. Последовательность копирований не обязательно влияет
  на запрашиваемую переменную: отдельный разбор учитывает эту зависимость.
  Переформулировки и переименования повторяют исходные миры и не считаются
  независимыми наблюдениями. Тестовые фразы используют известные учебные слова.
- Метки генерирует процедурный мир; второй алгоритм проверяет каждую запись
  обратным рекурсивным поиском. При выводе эти алгоритмы не вызываются.
  Эквивалентный формальный текст содержит ссылки на переменные, а не
  подставленные правильные значения копируемых переменных.

## Пилоты и заранее заданное решение

Два продолжения одного history_seed0: `direct` (цифра) и `trace` (все начальные
и последующие записи, затем `|цифра`). По 1200 обновлений, batch 16, AdamW,
lr 0.0005, weight decay 0.01, clip 1; warmup 50, cosine decay до 0.3 lr.
Dev оценивается в начале, на шагах 400, 800, 1200. Один CPU thread на запуск.
Пилоты имеют одинаковый sampling_seed 91900.

35% батчей — повторение старых задач (8000 примеров, по 2000 memory/code/sum/
logic). Остальные — новые задачи: 80% русский вход, 20% эквивалентный
формальный. Выборка с возвращением и группировкой длины русского входа;
счётчики предъявлений и токенов сохраняются. Сопоставлены число обновлений
и примеров; токены и время могут различаться и публикуются.

Выбор checkpoint: среднее answer accuracy на dev и dev_phrases; затем
legacy_dev accuracy; затем меньший token NLL. Выбор стиля — тот же порядок,
при полном равенстве direct. Бюджет подтверждения разрешён, только если
выбранный пилот достиг среднего dev не менее 50% и прибавил не менее 15
процентных пунктов относительно своего начального checkpoint. При провале
публикуем отрицательный пилот; не запускаем увеличенную сетку для количества.

## Подтверждение при прохождении порога

Выбранный стиль фиксируется до финального теста. Четыре архитектуры × три
seed; дополнительно три обычных MLP с теми же новыми задачами исключительно
на формальном языке. Итого 15 продолжений по 2400 обновлений, batch 16,
оценка dev каждые 800. Sampling seed = 92900 + seed. Контроли получают те же
латентные задачи в том же порядке, те же метки и прежние задачи; отличается
язык входа. Остальные настройки пилота сохранены. Большая внешняя языковая
модель, переводчик, парсер инструкций и калькулятор не подключаются.

Обучение всех вариантов завершается, карта выбранных checkpoint и русский
default фиксируются по dev, затем открываются финальные тесты. Если порог
пилота не пройден, финальные тесты остаются закрытыми.

Основные метрики: точность окончательного ответа с выученной остановкой,
точность полного вывода, точность внутри ролей запроса, обе верные стороны
смысловой пары. Дополнительно: формальные версии test/test_composed,
accuracy по длинам, изменения при переформулировке и переименовании.
Среднее и SD между тремя продолжениями; это не три независимых коннектома.
Исторический тест этапа 7 (960 заданий, ранее открыт) — только сохранение
навыков. Ограничение генерации 192 токена для новых задач и dev, 512 для
исторического финального теста. Начальные MLP checkpoint оцениваются на
финальных тестах только после общего открытия, для сравнения с контролями.

Ни основной default этапа 7, ни данные и веса прошлых этапов не меняются.
Отдельный `fly_russian.py` загружает русский checkpoint и свободно генерирует
ответ. Код, хеши, конфигурации, веса и исходные ответы сохраняются в репозитории.
