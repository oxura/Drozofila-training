# Этап 4: обучаемое управление действиями и поиск плана

## Что изменилось

В третьем этапе порядок обработки разрядов был задан кодом. В четвёртом сеть обучается выбирать движение указателя, конкретную цифру для записи, переход к следующей операции и остановку. Среда выполняет только выбранные действия; правильный ответ и учитель при выводе недоступны.

Шесть известных операций: копирование, разворот, отбор чётных, отбор нечётных, +1 и −1 к каждой цифре по модулю 10. В обычном режиме высокоуровневая программа дана человеком. В режиме цели написанный нами поиск в ширину составляет программу из этих операций, используя выученный исполнитель как модель переходов. **Алгоритм поиска не обучался.**

Это ограниченный эксперимент по управлению и композиции навыков. Новые элементарные правила, понимание произвольной речи и широкий интеллект здесь не продемонстрированы.

На данных длиной 256 коннектом с историей предыдущего действия получил 100.00% точных ответов. При использовании только внутренней памяти — 52.78%, а обычная GRU — 79.51%. Преимущество исходной структуры мозга в этом опыте не показано.

## Самостоятельное составление плана

Правильность найденного плана затем проверяется независимым функциональным эталоном. Контроллеры для этой проверки и seed 0 были выбраны до открытия результатов.

## Что означает результат для коннектома

Когда предыдущее действие доступно на входе, сеть может определять фазу процедуры по этому внешнему регистру. Это компактный выученный автомат. Когда регистр убран, фазу нужно хранить внутри рекуррентной сети. Сравнение с GRU показывает, даёт ли исходный биологический граф преимущество перед обычной сетью с памятью.

Контроль без рёбер сохраняет обучаемые входы, выходы, нелинейности и затухающее состояние отдельных элементов. Он не равен отсутствию вычислений. Контроль без памяти и истории не может надёжно чередовать запись и движение: запись не меняет его наблюдение, поэтому детерминированная политика повторяет её. Это проверка необходимости информации о фазе, а не конкурентная архитектура общего назначения.

Высокая точность сама по себе не является доказательством особой ценности коннектома. Нужно учитывать обычные MLP/GRU, перестановку рёбер, фиксированные веса и разницу в числе параметров. Преимущество над человеческим интеллектом этими задачами не измеряется.

## Обучение и границы обобщения

Обучение: 3600 программ с данными длины 0–6 и глубиной 1–3. Validation: 240 отдельных пар программа/данные. Учитель предоставляет правильное действие на каждом шаге. Метки генерирует код; ответы внешней языковой модели не использовались.

Из обучения исключены пары reverse→even, even→inc, inc→reverse, odd→dec, dec→copy, copy→odd. Финальная композиционная проверка содержит такие пары. Отдельно проверены длины данных 16, 64, 256 и глубины программ 4, 8, 16. В каждом основном наборе 75% целей непустые; первоначальный несбалансированный черновик, который не использовался для обучения, сохранён в `notes/stage4_unbalanced_draft`.

В обучающих трассах всего **140 различных локальных наблюдений** вида «операция, текущая ячейка, предыдущее действие». Система с таким интерфейсом учится небольшому набору локальных решений. Проверка новых длин и сочетаний не равна обучению неизвестным элементарным действиям.

| Финальный набор | Различных локальных наблюдений | Не встречались в обучении |
|---|---:|---:|
| test | 140 | 0 |
| composition | 140 | 0 |
| long_tape | 140 | 0 |
| long_program | 140 | 0 |
| stress | 138 | 0 |

36 подтверждающих запусков: пять сетей с внешним регистром × 3 seed, пять сетей только с внутренней памятью × 3 seed, коннектом с обоими механизмами × 3 seed и коннектом без обоих × 3 seed. Каждый запуск — 1200 шагов AdamW. Короткая разработка использовала 800 шагов и только train/validation.

Режимы с внешней историей и без памяти обучаются на отдельных наблюдениях с балансировкой классов действий. Рекуррентные режимы обучаются на полных траекториях. Поэтому сравнение этих семейств включает и архитектуру, и способ выборки обучающих примеров. Внутри семейства условия используют одинаковый способ обучения.

Параметры: коннектом/переставленные связи — 20328; фиксированные/отключённые рёбра — 12814; MLP с двумя слоями по 119 элементов — 20125; GRU из 64 элементов — 20110. Сеть делает четыре внутренних обновления на одно действие. Все запуски выполнены на CPU.

Код, бюджет, условия и проверка целей зафиксированы до финальной оценки. Контрольные суммы — в `results/stage4/confirmation/plan.json`, данные — в `data/stage4/manifest.json` и `data/stage4_planning/manifest.json`. Теперь эти тесты открыты; подстройка по ним потребует следующего независимого протокола.

## Что реализовано программой, а что выучено

| Часть | Происхождение |
|---|---|
| Граф из 256 нейронов и 7514 связей | Фрагмент настоящего коннектома |
| Входы, выходы, динамика, силы разрешённых рёбер | Искусственные обучаемые параметры |
| Двигаться влево/вправо, записать цифру, перейти к операции, остановиться | Предсказания сети |
| Лента, указатель, выходной буфер, семантика элементарного действия | Заданы средой |
| Предыдущее действие на входе | Дополнительный искусственный регистр в соответствующих режимах |
| Высокоуровневая программа в режиме --program | Задаёт пользователь |
| Программа в режиме --goal | Находит написанный нами поиск по выученным переходам |
| Русские названия команд | Ограниченное программное отображение в имена операций |

Среда `stage4_env.py` применяет действия одинаково при любой операции — это отдельно проверено. Учитель и функциональный эталон находятся в `stage4_tasks.py`; вывод модели и планировщик их не импортируют. Испорченная сеть не получает правильный ответ из запасного алгоритма. Внутренний программный счётчик двигается только по предсказанному NEXT; HALT тоже предсказывает сеть.

Для реактивных моделей можно предварительно вычислить их предсказания для всех 1260 комбинаций наблюдения. Такой кэш содержит ответы модели, а не учителя. Прямой и табличный вывод сверены на длинной задаче и глубокой программе. Модели с непрерывной внутренней памятью всегда исполняются непосредственно.

## Использование

```bash
python restore_large_files.py
python fly_program.py --program 'разверни | чётные | +1' --data '1 2 3 4' --trace
python fly_program.py --data '1 2 3' --goal '4 3 2'
python smart_fly.py 'сложи 99999999999999999999 1' --verify
```

Первый пример выдаёт `[5, 3]` за 30 выбранных сетью действий. Во втором примере поиск находит программу `reverse → inc`. Предыдущая арифметика, короткая память и шаблоны кода остаются отдельными сохранёнными моделями. Интерактивный ввод не обучает веса.

Воспроизведение отдельного запуска в новом каталоге:

```bash
python stage4_train.py --mode hidden --conditions fly --seeds 0 --steps 1200 --eval-every 300 --output results/stage4/reproduction
```

Продолжение: сначала скопировать каталог запуска с best.pt и last.pt, затем передать скопированный last.pt в `--resume` и увеличить `--steps`. Восстанавливаются веса, оптимизатор и RNG. Изменение общего бюджета пересчитывает cosine-расписание; оно не совпадает с непрерывным обучением с новым бюджетом с самого начала. На отдельной копии проверено продолжение 800→801.

## Следующие исследовательские цели

1. Учить выбор высокоуровневой программы и новые правила по демонстрациям, измеряя перенос на целые исключённые семейства правил. Сейчас эту часть заменяет внешний поиск.

2. Добавить задачи, где необходимы несколько адресов памяти, перестановки и восстановление после ошибки. Новые интерфейсы должны быть одинаковыми у коннектома и обычных сетей.

3. Проверять длинные одинаковые входы и устойчивость внутренней памяти. Короткие успешные траектории могут скрывать затухание состояния или нестабильный цикл действий.

4. Учить новые задачи последовательно и измерять забывание старых. Текущие модули обучаются раздельно; их объединение интерфейсом не доказывает перенос знаний между ними.

5. Масштабировать коннектом после контролируемых сравнений нескольких фрагментов. Больший граф сам по себе не обеспечивает более широкий интеллект.
