# FlyBrain Lab — обучаемые модели на основе коннектома

План дальнейшего развития: [память, перенос и управляемый рост сети](ROADMAP_BROAD_INTELLIGENCE.md).
Это предложения следующих опытов; новые результаты обучения в нём не заявлены.

## Шестой этап: одна нейросеть для вычислений по тексту

Текущий отчёт — **[STAGE6_RESULTS.md](STAGE6_RESULTS.md)**,
протокол — [STAGE6_PROTOCOL.md](STAGE6_PROTOCOL.md).
Один checkpoint с общими параметрами обучается суммам, вложенной логике
и коротким программам с переменными. Модель самостоятельно генерирует
значения операндов, промежуточные вычисления и ответ. В её выводе нет
внешнего арифметического решателя или правильных состояний регистров.

Сравниваются 24 кандидата: прямые ответы и подробные шаги, обучаемое
копирование, учебный блок простых упражнений, обычный MLP, исходные,
перемешанные и отсутствующие связи. По три seed и 8000 шагов; четыре
законченных пилота переиспользованы, двадцать обучений новые. Итоговый
отчёт включает все seed, проверки длин, сочетаний и новых имён переменных.

```bash
python fly_reason.py 'сумма 7,5,11,15'
python fly_reason.py 'логика xor(1,and(1,0))' --json
python fly_reason.py 'код a=2;b=3;c=0;d=1;a=(a+b)%10;?a'
```

Это команды для проверки модели, а не гарантированно правильные ответы.
Модель по умолчанию выбирается по validation до открытия окончательного
теста; путь сохранён в `results/stage6/default_model.json`. Другие веса
можно передать через `--checkpoint`. Приложены данные, best/last с
оптимизатором и RNG, журналы, все финальные предсказания и отрицательные результаты.

Это небольшая формальная модель, а не широкий интеллект или полная
эмуляция мухи. Используются 256 узлов из полного источника в 138639
нейронов; большая часть параметров новой архитектуры искусственная.
Новая сеть обучена с нуля: предыдущие навыки не объединены в её весах.
Памятка продолжения — [CONTINUE.md](CONTINUE.md), исследовательские гипотезы —
[notes/stage6_research.md](notes/stage6_research.md).

## Пятый этап: новое правило по демонстрациям

Текущий отчёт — **`STAGE5_RESULTS.md`**, точный протокол — `STAGE5_PROTOCOL.md`.
Новая модель получает примеры неизвестной бинарной зависимости и отвечает
на новые входы. Целые семейства правил исключены из обучения и validation.
Сравниваются исходный граф, изменённый граф, фиксированные/отсутствующие связи,
обычные MLP и архитектура без структурированной памяти: 21 подтверждающий
запуск по 6000 шагов, по три seed на каждое сравнение.

```bash
python fly_rules.py --examples-file data/stage5/demo.json --suggest
python fly_rules.py --examples '00000000=0;10000000=1;01000000=1;11000000=0' --query '10100000;01100000' --suggest
```

`--suggest` предлагает следующий вход, ответ на который должен дать человек.
Веса модели при этом не обновляются: новые демонстрации меняют временную память.
Четырёх примеров в короткой команде может быть недостаточно для однозначного
правила; JSON сообщает вероятность и отдельно проверенную однозначность
в ограниченном классе гипотез.

Память перебирает подмножества до трёх существенных бинарных координат и
вычисляет статистики программно. Сеть учится оценивать полезность этих частей
памяти. Это сильная искусственная помощь, не полная эмуляция мозга и не
самостоятельное изобретение произвольных алгоритмов. Структурная память и
нейронная оценка её частей сравниваются с простыми написанными алгоритмами.

Учебные данные, веса best/last, оптимизатор, RNG, журналы, предсказания,
ограничения и отрицательные результаты включены в `data/stage5` и
`results/stage5`. Предыдущие четыре этапа не перезаписаны; их навыки остаются
отдельными модулями. Продолжение — `CONTINUE.md`.

Это точное восстановление 100804642 байт с проверкой SHA-256; доступ к внешнему

```bash
python fly_program.py --program 'разверни | чётные | +1' --data '1 2 3 4' --trace

python smart_fly.py 'сложи 99999999999999999999 1' --verify
```

В четвёртом этапе сеть выбирает движение указателя, цифру для записи, переход

По `--goal` её ищет написанный нами поиск в ширину, используя выученный
исполнитель для предсказания результатов действий. Сама сеть не обучалась
алгоритму поиска и не изобретала список доступных операций.

Обучение, проверки и ограничения: `STAGE4_RESULTS.md`, `CONTINUE.md`, `AGENTS.md`.

## Третий этап: арифметический модуль и общий интерфейс

Актуальный отчёт: **`STAGE3_RESULTS.md`**. Отчёты, данные и веса первых двух
этапов сохранены. Новый `smart_fly.py` использует арифметическую модель третьего
этапа и по командам `код`, `повтори`, `разверни` обращается к прежней модели.
`infer.py` по-прежнему доступен отдельно для второго этапа.

```bash
python smart_fly.py 'сложи 99999999999999999999 1' --verify
python smart_fly.py 'вычти 5 12'
python smart_fly.py '(12345+67890)*(73-12)' --compiled
python smart_fly.py 'умножь -123456789 37' --verify --json
python smart_fly.py 'код сложи u x'
python smart_fly.py --interactive --compiled
```

Сеть обучается цифре ответа и переносу на всех 860 элементарных переходах
сложения, вычитания и умножения на одну цифру. Порядок разрядов, регистр переноса,
обработка знака, разбор выражений и составление многозначного умножения заданы
нами. Это существенная алгоритмическая помощь. Перенос на новые длины означает
композицию известных шагов; он не доказывает свободное владение математикой,
русским языком или преимущество биологического графа.

По умолчанию цифры и перенос каждый раз предсказывает сеть. `--compiled`
предварительно вычисляет её предсказания для конечного набора состояний и
использует их как ускоренную таблицу; правильные ответы вместо предсказаний
не подставляются. `--verify` проверяет согласованность через другие выученные
операции, но не даёт гарантии правильности. Ввод команд сам по себе не обучает.

Воспроизведение, протоколы сравнения и дальнейшее обучение описаны в
`STAGE3_RESULTS.md` и `CONTINUE.md`. Третий этап не изменяет веса второго.

## Второй этап: более разнообразные задания и память входа

Актуальные результаты: **`STAGE2_RESULTS.md`**. Первый опыт сохранён в
`RESULTS.md`, а его данные и checkpoints остаются доступными.

Добавлены `stage2_tasks.py`, `stage2_model.py`, `stage2_train.py`,
`stage2_evaluate.py`, `stage2_checks.py` и `stage2_report.py`. По умолчанию
`infer.py` теперь загружает улучшенную модель второго этапа, seed 0.

Примеры после установки зависимостей:

```bash
python infer.py 'повтори 1 2 3'
python infer.py 'код вычти u x'
python infer.py 'сложи 12 7' --json
python infer.py --interactive
```

Интерактивный режим выдаёт ответы из сохранённых весов и сам их не обновляет.
Продолжение обучения запускается отдельной командой `stage2_train.py`.

Второй этап содержит 11 952 учебных примера: арифметика с числами 0–19,
копирование и разворот последовательностей длины 2–5 из цифр и имён,
Python-функции с 12 возможными именами аргументов. Итоговая проверка использует
отдельные группы операндов, последовательностей и пар аргументов. Длины 6–7
проверяются отдельно как перенос за пределы учебных длин. Открытого русского
словаря, аудио и произвольных программ в этом наборе нет.

Новая модель сохраняет состояния нейронов после входных токенов. Во время
ответа она обучается выбирать из этих состояний полезный контекст и снова
подаёт его в рекуррентную сеть. В выходе нет готового калькулятора или
программного копирования нужных токенов. **Эта память и механизм внимания
добавлены искусственно; их нет в скачанном коннектоме.** Контроль без рёбер
отделяет их эффект от эффекта графа. Также обучена обычная GRU из 80 нейронов
с той же памятью входа: 52 001 параметр против 49 579 у улучшенной модели
с коннектомом. В обеих — обучение по тем же данным и одинаковое число шагов.

Подбор модели читает только train/validation. Программа финальной оценки
запускается отдельно, после окончания всех запусков и сохранения плана.
Прошлый тест не используется как доказательство улучшения: новая и старая
архитектуры заново обучены и проверены в одинаковом втором протоколе.

```bash
python stage2_tasks.py
python stage2_checks.py
python stage2_train.py --variants memory_rate --conditions fly --seeds 0 --steps 2400 --output results/stage2/reproduction
python stage2_train.py --resume results/stage2/reproduction/memory_rate_fly_seed0/last.pt --steps 3000
```

Повторная генерация данных проверяет их совпадение и не заменяет другой набор
молча. При продолжении обучения с увеличенным числом шагов cosine-расписание
скорости пересчитывается на новый общий бюджет; это не эквивалент запуска с
таким бюджетом с самого начала. Состояния оптимизатора и RNG восстанавливаются.
Протокол: `results/stage2/protocol.json`; зафиксированный план сравнений:
`results/stage2/confirmation/plan.json`. Все тесты этого этапа после отчёта
считаются открытыми; для следующего исследования нужен отдельный финальный тест.

## Что именно моделируется

Полный источник содержит 138 639 нейронов, 15 091 983 направленных пар и
54 492 922 контакта, агрегированных по этим парам. Число пар и число отдельных
синапсов — разные величины. Проверено соответствие индексов исходным ID.

Первый обучаемый фрагмент содержит 256 нейронов и 7 514 направленных связей,
около 0,185% нейронов источника. Выбор: обход сильных соседних связей от нейрона
с максимальной суммарной исходящей абсолютной силой. Это выбор структуры для
дешёвого опыта, не случайная репрезентативная выборка и не выделенный речевой
центр. Связи с оставшейся частью мозга в обучаемый фрагмент не входят.

Сила каждой существующей связи обучается; её знак сохраняется. Параметризация:
`w = sign(source) * normalized_log1p(abs(source)) * exp(clamp(gain, -4, 4))`.
Начальная нормировка по входящим связям задаёт их L2-норму 0,65. Нулевые в
коннектоме связи остаются нулевыми. Для скорости небольшой граф умножается
как плотная матрица, но обучаемых рекуррентных параметров только 7 514.

`rate`: состояние обновляется как `0.25*h + 0.75*tanh(input + W*h)`.
`lif`: `u = 0.85*v + input + W*spikes`, импульс возникает при `u > 1`,
после него из потенциала вычитается 1. Обучение импульсов использует
приближённый градиент `1/(1+5*abs(u-1))²`. Выход читается из потенциалов.

Шаг равен одному текстовому токену, а не миллисекунде биологического времени.
Нет исходных временных задержек, рефрактерности, морфологии и полной биохимии.
Вход — искусственная обучаемая таблица токенов, выход — обучаемое линейное
преобразование в вероятности токенов. Между ними только состояние данной
рекуррентной сети; внешней языковой модели и готового решателя в ответах нет.
Вход и выход подключены ко всем выбранным нейронам, а не к биологическим
органам чувств. Поэтому результат относится к этой модифицированной системе.

Исходная модель Brian2 проверяется отдельно, без обучения. В обёртке удалено
обнуление необъявленной переменной `w` из строки reset исходного кода.
Сам файл источника не менялся. Это численная проверка запуска, а не повторение
экспериментов статьи и не проверка поведения животного.

## Задания и честная проверка

1. Арифметика: «сложи», «вычти», «максимум», «минимум» для двух цифр.
2. Память: повторить или развернуть последовательность из трёх цифр.
3. Код: вывести Python-функцию из небольшой грамматики сложения, вычитания,
   `min` и `max`, сохранив имена двух аргументов. Это шаблонная генерация кода,
   не создание новых алгоритмов или работа с реальным репозиторием.

Данные получены алгоритмически, из явно заданных правил. Словарь строится
только по обучающей выборке; числа разбиваются на отдельные цифры. При проверке
арифметики нет учебных пар чисел, даже в обратном порядке. Для памяти проверяются
новые последовательности; для кода — новые упорядоченные пары имён аргументов.
Отдельно проверяется новое сочетание уже знакомых слов в формулировке команды.

Три условия в каждой архитектуре и по три случайных инициализации:

- `fly`: обучаются существующие связи реального фрагмента и вход/выход.
- `rewired`: переставлены адресаты связей; входящая и исходящая степень
  каждого нейрона, число рёбер и число обучаемых параметров сохраняются.
  Сила прикреплена к исходящему ребру; распределение по получателям и нормировка
  могут измениться. Это контроль структуры, не всех возможных свойств сети.
- `frozen`: исходные рекуррентные связи фиксированы, обучаются только вход/выход.

Веса выбираются по средней точности трёх типов заданий на validation.
Тестируется самостоятельная генерация до `<eos>`, без подстановки верных
предыдущих ответов. Код дополнительно проверяется на пяти парах числовых
входов. Синтаксическая корректность и прохождение тестов отмечены отдельно.
Удаление всех рекуррентных связей после обучения — дополнительная абляция,
не отдельная обученная контрольная сеть. Одинаковые правила обучения во всех
трёх условиях; подбор параметров отдельно под каждую сеть не проводился.

Этого пилота недостаточно для вывода о преимуществе коннектома в целом:
исследован один фрагмент, три seed, небольшой искусственный язык и ограниченный
бюджет обучения. Аудио, свободный русский, новые алгоритмы, сознание и сходство
обучения с живой мухой здесь не проверяются.
