**Продолжение проекта: этап 7 в работе**

Основной репозиторий: https://github.com/oxura/Drozofila-training.
Предыдущая памятка: notes/stage6_CONTINUE.md. Сначала читайте AGENTS.md,
STAGE7_PROTOCOL.md, ROADMAP_BROAD_INTELLIGENCE.md и
results/stage7/confirmation/plan.json.

Завершены шесть пилотов по 1600 шагов. Увеличенный вес конечного ответа
ухудшил validation, поэтому подтверждение использует прежнюю среднюю
токенную цель. Исходники двух наборов пилотов сохранены в notes/stage7_*_source.
Исправлен контроль расширения: в подтверждении новые входные признаки
независимы, выход из них изначально нулевой. Пилот с дублированием узлов
сохраняется как исторический, без утверждения о росте эффективной ёмкости.

Зафиксированы 24 запуска: восемь вариантов × seed 0/1/2 × 8000 обновлений,
batch 16, lr 0.0005, один CPU-поток на модель. Запущены восемь процессов
обучения. Все варианты продолжают соответствующие best.pt этапа 6,
оптимизатор новый. Никакие модели не обучаются от обычного вызова CLI.

Учебный набор: 28000 новых строк плюс отдельный replay только старого train
(28000). Validation 480. Новый test 960; отдельные длины 16/32, два вида
переименования, парные контрфактические изменения. Учитель программный;
в neural inference нет парсера задачи и правильного состояния регистров.
Все финальные наборы пока закрыты для предсказаний моделей.

Проверки данных, причинности, cached/full, сохранения функции и градиентов:
results/stage7/checks.json. Профилирование: results/stage7/profile.json.
Проверка evaluator выполнялась только на validation.

Команды из корня проекта:

```bash
python stage7_run.py train --jobs 8
python stage7_run.py evaluate --jobs 4
```

Первую команду вызывайте после проверки, что предыдущий orchestrator уже
не работает. Она пропускает законченные запуски и продолжает прерванные
по last.pt с тем же планом. Веса, optimizer и RNG сохраняются через 2000
обновлений. Перед evaluate должны закончиться все 24 запуска. Evaluator
фиксирует hashes checkpoint и выбор по validation до первого нового теста.
После открытия финальных результатов менять обучение в этом протоколе нельзя.

Код CLI этапа 7 — fly_memory.py; модель по умолчанию будет назначена после
окончания подтверждающих обучений. До этого можно явно передать --checkpoint
на завершённый пилот. Ответы могут быть ошибочными. Этап 6 и его CLI сохранены.

Большая часть модели искусственная. Графовая ветвь использует тот же фрагмент
256 узлов / 7514 связей; полноценный коннектом и широкий интеллект не получены.
