**Неизменяемый эксперимент**

План confirmation/plan.json содержит 24 обучения: 8 вариантов × 3 seed,
8000 шагов каждый. Данные, исходники, исходные веса и настройки заморожены;
stage7_run.verify() проверяет их хеши. Финальный тест уже был открыт,
выбрана history_seed1. Не выбирать новую модель и не менять обучение по тесту.

После потери рабочей папки из GitHub восстановлены 14 завершённых обучений.
Недостающие 10 воспроизводятся с теми же seed, данными и конфигурациями.
Это восстановление артефактов, не десять новых независимых подтверждений.
Протокол восстановления: results/stage7/recovery/restore_manifest.json.
Каждый last.pt включает optimizer/RNG, поэтому незавершённый запуск возобновим.
Не считать наличие best.pt признаком завершения: нужен validation.json.

**Порядок завершения**

1. Сначала проверить живые процессы; не запускать дубликаты. Python этой среды:
   /tmp/flybrain-venv/bin/python, Torch 2.14.0+cpu, NumPy 2.3.5; 8 CPU, без GPU.
2. `python stage7_run.py train --jobs 4` продолжает только незавершённые обучения.
3. `python stage7_restore_sources.py --jobs 2` завершает оценки 12 старых исходных
   моделей, проверяет готовые JSONL и пересчитывает метрики из сохранённых ответов.
   Генератор, размер batch 32 и лимит 512 не меняются. Учитель ответы не исправляет.
4. Когда все 24 validation.json готовы: `python stage7_audit.py`, затем
   `python stage7_recover.py freeze`. Проверить, совпадает ли карта 48 checkpoint
   с опубликованным до первого сбоя SHA256. Даже при несовпадении сохранить
   исходный marker и честно отметить воспроизведённые файлы.
5. Сначала опубликовать все завершённые checkpoint, затем
   `python stage7_recover.py evaluate --jobs 4`. Четыре процесса оценки по два
   потока занимают все 8 CPU; одновременно не запускать тяжёлое обучение.
6. `python stage7_verify.py`, `python stage7_report.py`. Проверить отчёт,
   рисунок, исходные предсказания и сравнение с ранее наблюдавшимися числами.
   Не выдавать старую округлённую сводку за текущий полный архив.
7. Опубликовать код, веса, данные, предсказания, отчёт; проверить remote main/tree.
   После этого обновить эту памятку и README ссылкой на STAGE7_RESULTS.md.

**Публикация**

Нативный git push здесь не авторизован; доступен подключённый GitHub app.
`tools/publish_github_snapshot.py` публикует неизменяемый staged snapshot,
проверяет ожидаемое дерево и исходный remote head, не применяет force push.
`tools/archive_stage7_progress.py` собирает согласованные промежуточные
checkpoint и делает их достижимыми в main. Файлы publisher в /tmp/flybrain-publish
содержат index, сообщение, cache уже загруженных blobs и receipt. Перед новым
snapshot завершить существующую публикацию; не менять её index во время загрузки.
Указанный SDK — неизменённый runtime library_hosted_apps.py; никаких credentials в Git.

**Следующий научный шаг**

Следовать ROADMAP_BROAD_INTELLIGENCE.md: память и выбор переменной, затем
длинное исполнение и выученная остановка. Во всех моделях этапа 7 доступен
полный предыдущий текст: это ещё не доказательство памяти после удаления
контекста. Новая настройка требует нового протокола и новых удержанных тестов.
Рост 256 → 512 → 1024 и перестройку графа проверять отдельно, с контролями
продолжения малой сети и большой сети с начала обучения. Широкий интеллект
и преимущество биологической топологии не продемонстрированы.
